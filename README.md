# Salon Booking Bot

Telegram-бот для автоматизации записи клиентов в салон красоты / барбершоп / к частным мастерам.
Стек: **Python 3.12, aiogram 3, PostgreSQL, SQLAlchemy 2 (async), Alembic, Docker**.
Внешних сервисов, кроме PostgreSQL, не нужно: напоминания и удержание слотов работают внутри
процесса бота (без Redis и отдельного воркера).

---

## Возможности

- Регистрация клиента через Telegram, ввод имени и телефона («Поделиться контактом» или вручную,
  с проверкой формата).
- Выбор услуги → выбор мастера **вручную** или **автоподбор** («ближайшее время» / «лучший рейтинг»).
- Портфолио мастера с перелистыванием, рейтинг и отзывы.
- Календарь: показываются только реально свободные интервалы (график, перерыв, выходные,
  блокировки и особые часы, длительность услуги, буфер между клиентами, часовой пояс).
- **Защита от двойного бронирования**: блокировка строки мастера в транзакции + проверка
  пересечений + частичный уникальный индекс PostgreSQL + повторная проверка перед созданием.
- **Временное удержание слота** (по умолчанию 5 минут), пока клиент оформляет запись.
- Уведомление мастеру о новой записи с кнопками «Подтвердить/Отклонить».
- **SMS** через подключаемый интерфейс `SMSProvider` (Twilio; без настроек бот работает через Telegram).
- «Мои записи»: перенос (новое время снова подтверждает мастер) и отмена — не позже чем за
  `MIN_CANCEL_HOURS` часов.
- Напоминания клиенту (по умолчанию за 24 ч и за 2 ч), утренний дайджест мастеру, автозавершение
  прошедших записей и просьба оставить отзыв. Каждое уведомление отправляется ровно один раз,
  даже после перезапуска.
- Отзывы: только после завершённой записи, один отзыв на запись, авто-пересчёт рейтинга.
- Админ-панель: записи на сегодня / предстоящие, редактирование записи (перенос, смена мастера,
  статус, отмена), мастера, услуги, клиенты, отзывы, статистика, рассылка, экспорт CSV.
- Локализация ru / ro / en (по умолчанию русский).

## Деплой на Railway

Бот работает через long polling, поэтому ему **не нужен** публичный домен и порт.

1. Создайте бота у **@BotFather** (см. ниже) и получите токен.
2. Залейте папку проекта в GitHub-репозиторий (или используйте `railway up` из Railway CLI).
3. В Railway: **New Project → Deploy from GitHub repo** → выберите репозиторий.
   Railway сам найдёт `Dockerfile` и `railway.json` (сборка из Dockerfile, перезапуск при сбое).
4. В том же проекте: **+ New → Database → PostgreSQL**.
5. Откройте сервис бота → **Variables** и добавьте:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от BotFather |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (ссылка на переменную сервиса Postgres) |
   | `ADMIN_IDS` | ваш Telegram ID (можно несколько через запятую) |
   | `SALON_NAME`, `SALON_ADDRESS`, `SALON_PHONE` | данные салона |
   | `SEED_DEMO` | `true` — создать демо-данные при первом запуске, `false` — пустая база |
   | `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | `15` (рекомендуется) — время между SIGTERM и SIGKILL при редеплое, чтобы бот успел дообработать текущие нажатия |

   Остальные переменные — в `.env.example` (все необязательные). `SALON_*`, `TIMEZONE`,
   `CURRENCY` и `MASTER_TELEGRAM_ID` можно добавить или поменять и позже — они применяются
   при следующем запуске.
   Формат `postgresql://…`, который выдаёт Railway, бот преобразует для asyncpg сам.
6. **Deploy**. В логах должны появиться `migrations.applied`, `seed.checked` и `Start polling`.
   Миграции применяются автоматически при каждом старте (если база уже актуальна — ничего не делается).

Важно:
- Держите **одну реплику** сервиса: два процесса с одним токеном конфликтуют в Telegram
  (`TelegramConflictError`).
- Не включайте **Serverless / App Sleeping**: бот работает через polling, входящих запросов у
  него нет, и «уснувший» сервис перестанет отвечать и слать напоминания.
- Если проект лежит в подпапке репозитория, укажите её в **Settings → Root Directory**.
- Состояние диалогов (FSM) хранится в памяти, поэтому при редеплое незаконченный диалог
  сбрасывается — бот ответит «кнопка устарела, начните заново». Нажатие любой кнопки главного
  меню тоже завершает незаконченный шаг диалога. Записи, напоминания и всё
  остальное хранится в PostgreSQL и не теряется.
- Сообщения, отправленные боту во время перезапуска, не теряются — бот обработает их после старта.
- Если база ещё поднимается, бот ждёт её до ~60 секунд, а не падает.

## Быстрый старт (Docker Compose)

```bash
cp .env.example .env
# впишите BOT_TOKEN и ADMIN_IDS (ваш Telegram ID)
docker compose up --build
```

Бот сам применит миграции и (при `SEED_DEMO=true`) создаст тестовые данные: услуги, трёх
мастеров с расписанием и отзывами. Укажите `MASTER_TELEGRAM_ID`, чтобы первый демо-мастер был
реальным аккаунтом и получал уведомления о записях с кнопками подтверждения.
Откройте бота в Telegram и нажмите **/start**.

## Локальный запуск (без Docker)

Нужен локально запущенный PostgreSQL.

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

cp .env.example .env
# DATABASE_URL=postgresql+asyncpg://salon:salon@localhost:5432/salon

python -m app.main            # миграции + демо-данные + бот
```

Миграции и сид можно запускать и отдельно: `alembic upgrade head`, `python -m app.seed`.

1. В Telegram откройте **@BotFather** → команда `/newbot`.
2. Задайте имя и username (должен заканчиваться на `bot`).
3. Скопируйте выданный **токен** в `BOT_TOKEN`.
4. Рекомендуется: `/setcommands` →
   ```

   ```

## Как добавить администратора и мастеров

**Администратор.** Узнайте свой Telegram ID (например, через @userinfobot) и впишите его в
`ADMIN_IDS` (можно несколько через запятую). При первом сообщении боту роль станет `admin`,
и появится кнопка «⚙️ Админ-панель». `ADMIN_IDS` — источник истины: если убрать ID из списка,
роль администратора снимается при следующем сообщении этого пользователя. Постоянного
администратора вне списка можно задать в БД ролью `owner`. Права проверяются на сервере —
данным из кнопок не доверяем.

**Мастера.** Мастера заводятся через `app.seed` (демо) или напрямую в БД: `User` с
`role=master`, затем `Master`, привязка услуг (`master_services`) и график (`schedules`).
Чтобы мастер получал уведомления, его `users.telegram_id` должен быть реальным и мастер должен
хотя бы раз написать боту `/start`. Демо-мастера имеют фиктивные ID (1–3) — уведомления им не
отправляются (кроме мастера, привязанного через `MASTER_TELEGRAM_ID`).

## Тесты

```bash
pip install -e ".[dev]"
pytest -q
ruff check .
mypy app
```

Тесты работают на SQLite в памяти, PostgreSQL и `.env` для них не нужны. Покрыты: свободные слоты,
выходной/особые часы, перерыв, длительность, буфер, двойное бронирование и пересечения, перенос,
отмена (в т.ч. запрет позднего), защита отменённых записей, смена мастера, автоподбор, отзывы,
удержание слота, нормализация `DATABASE_URL`, проверка телефона, права администратора.

## Защита от двойного бронирования (как это работает)

1. Любое действие, занимающее время мастера (создание, перенос, смена мастера, восстановление
   отменённой записи), сначала блокирует строку мастера (`SELECT … FOR UPDATE`) — параллельные
   бронирования к одному мастеру выполняются по очереди.
2. Под этой блокировкой ищутся пересекающиеся активные записи; если есть — `SlotTakenError`.
3. Частичный уникальный индекс `(master_id, start_at)` по активным записям — последний рубеж;
   вставка идёт в SAVEPOINT, поэтому нарушение откатывает только её.
4. Время из кнопки повторно проверяется по расписанию перед созданием записи (кнопки можно подделать).
5. Удержание слота в памяти не даёт двум клиентам одновременно оформлять пересекающиеся слоты.

## Безопасность

- Токены и ключи только в переменных окружения; `.env` не попадает в Docker-образ (`.dockerignore`);
  контейнер работает не от root.
- Логи структурированные (JSON), без секретов; телефоны в логах SMS маскируются.
- Проверка ролей на сервере, проверка владельца записи при отмене/переносе, проверка статуса
  записи (отменённую запись нельзя «воскресить» старой кнопкой).
- Сообщения отправляются без HTML-разметки — пользовательский текст не ломает отправку.
- Экспорт CSV защищён от формульных инъекций.
- Ошибки логируются, пользователю показывается понятное сообщение без traceback.

## Резервное копирование БД

```bash
# Docker Compose
docker compose exec db pg_dump -U salon salon > backup_$(date +%F).sql
cat backup.sql | docker compose exec -T db psql -U salon salon
# Railway: используйте DATABASE_PUBLIC_URL сервиса Postgres
pg_dump "$DATABASE_PUBLIC_URL" > backup_$(date +%F).sql
```
