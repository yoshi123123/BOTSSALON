# Salon Booking Bot

Telegram-бот для автоматизации записи клиентов в салон красоты / барбершоп / к частным мастерам.
Стек: **Python 3.12, aiogram 3, PostgreSQL, SQLAlchemy 2 (async), Alembic, Redis, Arq, Docker**.

Это **MVP**: рабочий сквозной сценарий записи, уведомления, напоминания, отзывы и базовая
админ-панель. Список того, что можно добавить во второй версии — в конце файла.

---

## Возможности MVP

- Регистрация клиента через Telegram, ввод имени и телефона («Поделиться контактом»).
- Выбор услуги → выбор мастера **вручную** или **автоподбор** («ближайшее время» / «лучший рейтинг»).
- Портфолио мастера с перелистыванием, рейтинг и отзывы.
- Календарь: показываются только реально свободные интервалы (учитывает график, перерыв,
  выходные, блокировки, длительность услуги, буфер между клиентами, часовой пояс).
- **Защита от двойного бронирования**: транзакция + `SELECT … FOR UPDATE` по пересечению
  интервалов + частичный уникальный индекс (PostgreSQL) + повторная проверка перед коммитом.
- **Временное удержание слота** в Redis (по умолчанию 5 минут).
- Telegram-уведомление мастеру о новой записи с кнопками «Подтвердить/Отклонить» — без входа в
  общую админ-панель.
- **SMS** через подключаемый интерфейс `SMSProvider` (реализация Twilio; при отключённом/
  ненастроенном SMS бот работает через Telegram).
- «Мои записи»: перенос, отмена (с запретом отмены позже, чем за N часов).
- Напоминания клиенту за 24 ч и за 2 ч + утренний дайджест мастеру (фоновый воркер Arq,
  переживает перезапуск).
- Отзывы: только после завершённой записи, один отзыв на запись, авто-пересчёт рейтинга.
- Админ-панель: записи на сегодня, статистика, рассылка, экспорт CSV.
- Локализация ru / ro / en (по умолчанию русский), тексты вынесены в отдельные файлы.

## Быстрый старт (Docker)

1. Создайте бота у **@BotFather** (см. ниже) и получите токен.
2. Скопируйте настройки и заполните:
   ```bash
   cp .env.example .env
   # впишите BOT_TOKEN и ADMIN_IDS (ваш Telegram ID)
   ```
3. Запустите:
   ```bash
   docker compose up --build
   ```
   Контейнер `migrate` применит миграции, затем поднимутся `bot` и `worker`.
4. Заполните тестовые данные (услуги, мастер, расписание):
   ```bash
   docker compose run --rm bot python -m app.seed
   ```
   Укажите `MASTER_TELEGRAM_ID` в `.env`, чтобы уведомления приходили реальному мастеру.
5. Откройте бота в Telegram, нажмите **/start**.

## Локальный запуск (без Docker)

Нужны локально запущенные PostgreSQL и Redis.

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

cp .env.example .env
# DATABASE_URL=postgresql+asyncpg://salon:salon@localhost:5432/salon
# REDIS_URL=redis://localhost:6379/0

alembic upgrade head          # миграции
python -m app.seed            # тестовые данные

python -m app.main            # терминал 1: бот
arq app.background.worker.WorkerSettings   # терминал 2: напоминания
```

## Как создать бота в BotFather

1. В Telegram откройте **@BotFather** → команда `/newbot`.
2. Задайте имя и username (должен заканчиваться на `bot`).
3. Скопируйте выданный **токен** в `BOT_TOKEN` в `.env`.
4. Рекомендуется: `/setcommands` →
   ```
   start - Главное меню
   ```
5. Чтобы кнопка «Поделиться контактом» работала, ничего дополнительно настраивать не нужно.

## Как добавить администратора и мастеров

**Администратор.** Узнайте свой Telegram ID (например, через @userinfobot) и впишите его в
`ADMIN_IDS` (можно несколько через запятую). При первом `/start` роль повысится до `admin`
автоматически, и появится кнопка «⚙️ Админ-панель». Доступ к админ-разделам проверяется по
Telegram ID / роли на стороне сервера — данным интерфейса не доверяем.

**Мастера.** В MVP мастера заводятся через `app.seed` или напрямую в БД: создаётся `User` с
`role=master`, затем `Master`, привязка услуг (`master_services`) и график (`schedules`).
Чтобы мастер получал уведомления, его `users.telegram_id` должен быть реальным (мастер должен
хотя бы раз написать боту `/start`). Полноценный UI управления мастерами из Telegram —
в планах второй версии.

## Архитектура

```
app/
  config.py            Pydantic Settings (секреты только из .env)
  main.py              точка входа: бот, диспетчер, middlewares, polling
  db/                  engine, session, ORM-модели
  repositories/        доступ к данным (users, catalog, appointments)
  services/            бизнес-логика: availability, booking, matching,
                       slot_hold, notifications
  handlers/            common, booking (FSM), my_appointments, master,
                       reviews, admin, errors
  keyboards/           callback-фабрики и построители клавиатур
  states/              FSM-состояния
  middlewares/         сессия БД + пользователь, инъекция зависимостей
  integrations/sms/    SMSProvider (Null + Twilio) + фабрика
  background/          Arq-воркер: напоминания, дайджесты
  locales/             ru / ro / en
  utils/               форматирование дат/времени
alembic/               миграции
tests/                 pytest
```

Бизнес-логика не зависит от Telegram и от конкретного SMS-провайдера: интерфейс можно заменить,
не переписывая слой `services`.

## Защита от двойного бронирования (как это работает)

1. Частичный уникальный индекс `(master_id, start_at)` по активным записям (PostgreSQL).
2. В той же транзакции `overlapping_active(... FOR UPDATE)` блокирует пересекающиеся строки —
   два одновременных бронирования сериализуются.
3. Redis-hold не даёт двум клиентам «держать» один слот в UI-окне оформления.
4. Перед коммитом доступность проверяется повторно; при конфликте — `SlotTakenError`,
   слот освобождается, клиенту предлагается другое время.

Источник истины — база данных; Redis лишь улучшает UX.

## Безопасность

- Токены и ключи только в `.env`, в код не попадают; логи структурированы и не пишут секреты.
- Проверка ролей на сервере, проверка владельца записи при отмене/переносе.
- Телефон клиента виден только назначенному мастеру и администратору.
- Идемпотентность: удержание слота + повторная проверка + обработка двойных нажатий.
- Ошибки логируются, пользователю показывается понятное сообщение без traceback.

## Резервное копирование БД

# бэкап

# восстановление
cat backup.sql | docker compose exec -T db psql -U salon salon
```
